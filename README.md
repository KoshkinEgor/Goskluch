
# Интеграция Госключ

**Goskluch** — это платформа, предназначенная для автоматизации передачи документов на подписание усиленной квалифицированной электронной подписью (УКЭП) через систему «Госключ». Система выступает в роли интеграционного шлюза, обеспечивающего взаимодействие с государственными информационными системами, такими как СМЭВ 3, ЕПГУ и ЕСИА.

## Цели проекта

1. **Автоматизация документооборота**: Упрощение и ускорение процесса инициации запросов на подписание документов юридически значимыми электронными подписями.
2. **Стандартизация интеграции**: Предоставление унифицированного API для взаимодействия со сложными протоколами государственных систем (SOAP/MTOM для СМЭВ 3, REST для ЕПГУ/ЕСИА).
3. **Надежность доставки**: Гарантированная обработка запросов с механизмом повторных попыток (retry) и фоновыми задачами для обработки "зависших" статусов.
4. **Безопасность и разграничение доступа**: Обеспечение целостности данных, безопасное хранение документов и строгая аутентификация пользователей на основе JWT и ролевой модели.

## Ключевые возможности

### Управление заказами и документами
- Загрузка пакетов документов для подписания с валидацией типов файлов.
- Автоматическое формирование ZIP-архивов, содержащих оригиналы документов и файлы открепленной электронной подписи (`.sig`) для скачивания.
- Отслеживание статусов заказов в реальном времени (инициирован, в процессе, подписан, отклонен).

### Интеграция с государственными системами (Эмуляция и подготовка к продакшену)
- **СМЭВ 3 (Система межведомственного электронного взаимодействия)**: 
  - Поддержка отправки SOAP-запросов с MTOM-вложениями (`RequestSignUkep`).
  - Обработка асинхронных ответов: получение подписи, отказ в подписании или коды ошибок.
- **ЕПГУ (Единый портал государственных услуг)**: Инициация заказов на подпись и опрос статусов их выполнения.
- **ЕСИА (Единая система идентификации и аутентификации)**: Эмуляция OAuth2/OpenID Connect flow для получения токенов доступа (`access_token`, `id_token`).

### Администрирование и безопасность
- Аутентификация пользователей с использованием JWT-токенов.
- Ролевая модель доступа (`admin`, `user`) с защитой эндпоинтов управления пользователями и системными настройками.
- Гибкая настройка параметров интеграции (мнемоника, код сервиса, регион) через панель конфигурации.

## Технологический стек

- **Backend**: C# 12 / .NET 9.0 (ASP.NET Core Minimal API).
- **Оркестрация и фоновые задачи**: `IHostedService` для обработки отложенных и повторных запросов (`SmevDeadRequestWorker`, `EpguDeadRequestWorker`).
- **Работа с данными**: Entity Framework Core (для управления заказами, пользователями и конфигурациями).
- **Сетевое взаимодействие**: `IHttpClientFactory` для типизированных HTTP-клиентов, парсинг XML (LINQ to XML) и обработка multipart/MTOM-сообщений.
- **Frontend (в составе сервиса)**: JavaScript, CSS (для базовых клиентских компонентов или тестовых интерфейсов).

## Текущее состояние и планы развития

### Текущие особенности реализации
- Взаимодействие с внешними системами (СМЭВ, ЕПГУ, ЕСИА) на данный момент реализовано через **Mock-сервисы**, что позволяет разрабатывать и тестировать бизнес-логику без доступа к контурам государственных систем.
- Файлы документов хранятся в локальной файловой системе (`DocumentsStorage`).
